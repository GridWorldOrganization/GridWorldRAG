## 3. Google API レート制限に引っかかる

> **tobisako**: ファイル一覧取得が遅い。
>
> **claude**: 並列化して高速化します。4スレッドで。

（実行後）

> **tobisako**: エラーでた。`User rate limit exceeded`。おそらくマルチにした影響だろう。
>
> **claude**: はい。4スレッドが同時に Google Drive API を叩き、QPS制限に到達しました。2スレッドに制限し、レート制限時にスレッド間で協調してバックオフする仕組みを入れます。
>
> **tobisako**: もし2スレッドが並行処理している最中にレート制限が出たら、少し間をあけて、スレッド同士が協調して再開できる機構にして。

`rate_lock` + `rate_backoff` で共有バックオフ時刻を管理。一方がレート制限を受けたら他方も待機する仕組みに。

## 4. ワーカーがタスクを取れずに遊んでいる

> **tobisako**: W1 が done 0 tasks でまだワーカータスク残っているはずなのに遊んでいる。修正。
>
> **claude**: `multiprocessing.Queue` のパイプ詰まりです。大きなデータをキューに入れると feeder スレッドが追いつかず、`get_nowait()` が空を返します。

対策を2段階で実施:
1. `get_nowait()` → ブロッキング `get()` + センチネル `None` 方式に変更
2. キューにはタスクID等の軽量メタデータのみ入れ、ファイルデータは pickle ファイル経由で渡す

> **tobisako**: これで動いた。

## 5. モニター画面がぐちゃぐちゃになる

> **tobisako**: 表示おかしい。W2が2行表示される。Ctrl+Cの行が何行も出る。
>
> **claude**: 全角文字を含む行がターミナル幅を超えて折り返し、カーソル移動量がずれています。

この問題は長い試行錯誤を経て解決:

> **tobisako**: カーソル位置が画面のいちばん左上に飛んでいるのが見える。
>
> **claude**: `clear` + `\033[H]` でカーソルが最上部に行き、ファイル一覧の上にモニターを上書きしていました。

| 試した方式 | 結果 |
|-----------|------|
| `\033[nA]` 相対カーソル移動 | ファイル一覧の後だとずれる |
| `clear` + `echo` | ファイル一覧が消える |
| `\033[H]` カーソル先頭移動 | ファイル一覧の上に上書き |
| **`tput sc/rc` カーソル保存/復元** | **成功** |

> **tobisako**: この画面CLI制御いいかんじ。このやりかたならうまくいく。さっきのやりかただとだめなてんを .md 記載して。

最終的に `tput sc/rc` + Python (`src/monitor_render.py`) で全行を一括生成する方式に落ち着いた。

## 6. Ctrl+C でゾンビが残る

> **tobisako**: Ctrl+C でコワーカーが残らないように改造して。もし .sh で実現できない場合は、別の方式を考えて。
>
> **claude**: Python 側でデーモンプロセス化 + シグナルハンドラで確実に子プロセスを殺します。
>
> **tobisako**: Ctrl+C おしたとき、子ワーカーが先にとまって、それを全部見届けてから親ワーカーが最終チェックし、そして親ワーカーも終了する仕組みにして。

3段構えの停止機構を実装:
1. `run_build.sh`: trap で `BUILD_PID` に kill
2. `build_parallel.py`: SIGTERM ハンドラで全ワーカーに `terminate()` → `join(timeout=10)` → `kill()`
3. `p.daemon = True` で親が死んだら子も自動終了

> **tobisako**: チェックして。
>
> **claude**: 全プロセス停止済みです。ワーカー残存ゼロ。Ctrl+C でクリーンに止まりました。
