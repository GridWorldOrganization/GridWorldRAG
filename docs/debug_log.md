# デバッグ記録

## NUL文字エラー (解決済み)

**現象**: `build_index.py` が1,403件目で `ValueError: A string literal cannot contain NUL (0x00) characters` で停止。

**原因**: PDFやドキュメントから抽出したテキストに NUL 文字 (`\x00`) が混入。PostgreSQL は NUL を含む文字列を受け付けない。

**対策**: `db.py` の `insert_chunks` で `title` と `content` から `\x00` を自動除去。

## シングルプロセスのボトルネック (解決済み)

**現象**: `build_index.py` で処理速度が約9件/分。75,000件の処理に推定1.5〜2時間。

**原因**: 1プロセスでAPI呼び出し→テキスト抽出→埋め込み生成を逐次実行。特に巨大ファイル（15,451チャンクの HTML、1,000チャンク超の技術書 PDF が37冊）がボトルネック。

**対策**: `build_parallel.py` で8ワーカー並列処理に移行。約5〜8倍の高速化。

## Google API レート制限 429 エラー (解決済み)

**現象**: ファイル一覧取得を4スレッド並列にしたところ `User rate limit exceeded` (429) が発生。

**原因**: 4スレッドが同時に Google Drive API を叩き、ユーザーあたりの QPS 制限に到達。

**対策**:
- 並列スレッド数を2に制限
- `_api_call_with_retry()` でエクスポネンシャルバックオフ付きリトライ（最大5回）
- スレッド間で `rate_lock` + `rate_backoff` を共有し、一方がレート制限を受けたら他方も待機

## multiprocessing.Queue パイプ詰まり (解決済み)

**現象**: 8ワーカー中4〜6が `done 0 tasks` で即終了。タスクを取得できていない。

**原因**: `multiprocessing.Queue` は内部的にパイプを使用。大きなデータ（数千ファイルのメタデータ）を `put` すると、feeder スレッドのパイプ書き込みが追いつかず、ワーカーの `get_nowait()` が空を返す。

**対策**:
1. `get_nowait()` → ブロッキング `get()` + センチネル `None` 方式に変更
2. タスクデータを2層に分離: キューには軽量メタデータのみ（数百バイト）、ファイルデータは pickle ファイル経由

## モニター画面のカーソル位置ずれ (解決済み)

**現象**: インデックス構築のモニター表示が壊れる。行が二重になる、カーソルが画面外に飛ぶ、Ctrl+C 後に表示が崩れる。

**原因**: ファイル一覧（20行超）が stdout に出力された後にモニターが開始。`\033[nA`（相対カーソル上移動）がファイル一覧の領域に突入。全角文字を含む行が `%.Ns` で途中切れして折り返しが発生。

**試行錯誤**:

| 方式 | 結果 |
|------|------|
| `\033[nA` 相対カーソル移動 | ファイル一覧の後だとずれる |
| `clear` + `echo` | ファイル一覧が消える、画面最上部に飛ぶ |
| `\033[H` カーソル先頭移動 | ファイル一覧の上に上書きしてしまう |
| `tput sc/rc` カーソル保存/復元 | **成功** |

**最終対策**: `tput sc` でモニター表示領域の先頭位置を保存し、毎回 `tput rc` で復元して上書き。各行は `\033[K` で行末クリア。Python (`src/monitor_render.py`) で全行を一括生成し、全角文字の問題を回避。

## Ctrl+C でのゾンビプロセス残存 (解決済み)

**現象**: `run_build.sh` を Ctrl+C で止めても、ワーカープロセスが残り続けてCPUを消費。

**原因**: `run_build.sh` の Ctrl+C が子プロセス（`build_parallel.py`）に伝播しない。`build_parallel.py` 内の `multiprocessing.Process` が daemon=True でも、親の Python プロセスが SIGTERM を受けてもワーカーに伝えない。

**対策**:
1. `run_build.sh`: trap で `BUILD_PID` に kill を送信
2. `build_parallel.py`: `signal.SIGINT/SIGTERM` ハンドラで全ワーカーに `terminate()` → `join(timeout=10)` → 生きていたら `kill()`
3. ワーカーは `p.daemon = True` で親プロセス終了時にも自動停止

## ワーカー間タスク間待機が長い (調査中)

**現象**: ワーカーがタスク完了後「待機中」で20秒以上止まることがまれに発生。

**調査状況**:
- タスク間の sleep は合計 1.6秒（`MONITOR_INTERVAL_MS` × 2）のみ
- `task_queue.get()` は即座に返るはず（キューにタスクが残っている）
- W6 等は即座に次のタスクを取得できており、全ワーカーで発生するわけではない
- デバッグログ `[DEBUG] Wn タスク間: 100%=... ready=... get前=...` を追加して原因特定中

**可能性**:
- 大きなファイル（巨大 PDF 等）の処理中にモニター更新タイミングと重なり、見かけ上「待機中」が長く見えた
- `multiprocessing.Queue` のパイプ書き込み遅延の再発
